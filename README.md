# Sea Routes

Веб-приложение для работы с морскими контейнерными маршрутами.

Бэкенд реализован на Go с использованием Gin. Для работы с базой данных используется GORM и PostgreSQL. Изображения и видео маршрутов хранятся в MinIO.

## Методы API

Все методы веб-сервиса имеют префикс `/api`.

| Метод | URL | Назначение |
|---|---|---|
| GET | `/api/sea-routes?min_distance_nautical_miles=4000&max_distance_nautical_miles=8000` | Получение списка опубликованных морских маршрутов с фильтрацией по расстоянию |
| GET | `/api/sea-routes/feed` | Получение ленты опубликованных маршрутов. Параметры `sea_route_id` и `next=true` позволяют получить конкретную или следующую запись |
| GET | `/api/sea-routes/draft` | Получение черновика текущего пользователя |
| POST | `/api/sea-routes` | Создание черновика маршрута и загрузка изображения и видео в MinIO |
| PUT | `/api/sea-routes/draft` | Заполнение полей черновика и публикация маршрута |
| DELETE | `/api/sea-routes/:id` | Логическое удаление маршрута текущего пользователя |
| POST | `/api/sea-routes/:id/likes` | Установка или снятие лайка. Тело запроса: `{"value": 1}` или `{"value": 0}` |
| POST | `/api/users` | Регистрация нового пользователя |
| POST | `/api/auth` | Заглушка аутентификации для лабораторной работы №4 |
| POST | `/api/logout` | Заглушка деавторизации для лабораторной работы №4 |

### GET `/api/sea-routes`

Метод возвращает только опубликованные маршруты.

Для фильтрации используются параметры:

- `min_distance_nautical_miles` — минимальное расстояние;
- `max_distance_nautical_miles` — максимальное расстояние.

В ответ также добавляется поле `is_creator`:

- `1` — текущий пользователь является создателем маршрута;
- `0` — маршрут создан другим пользователем.

### GET `/api/sea-routes/feed`

Без параметров возвращается первый опубликованный маршрут.

Для получения следующего маршрута используются параметры:

```text
sea_route_id=1
next=true
```

В ответ добавляется поле `is_liked`:

- `1` — текущий пользователь поставил лайк;
- `0` — лайк не поставлен.

### GET `/api/sea-routes/draft`

Возвращает черновик текущего пользователя.

У одного пользователя может быть только один черновик.

Если некоторые поля еще не заполнены, они присутствуют в JSON со значением `null`.

### POST `/api/sea-routes`

Запрос отправляется в формате `multipart/form-data`.

Передаются:

- `name` — название маршрута;
- `image` — файл изображения;
- `video` — файл видео.

Файлы сохраняются в MinIO, а их сгенерированные имена записываются в базу данных.

### PUT `/api/sea-routes/draft`

Для публикации передаются:

```json
{
  "distance_nautical_miles": 6420,
  "average_port_delay_hours": 96,
  "description": "Морской контейнерный маршрут"
}
```

После публикации маршрут становится доступен в списке и ленте.

### POST `/api/sea-routes/:id/likes`

Для установки лайка:

```json
{
  "value": 1
}
```

Для снятия лайка:

```json
{
  "value": 0
}
```

### DELETE `/api/sea-routes/:id`

Удаление выполняется логически.

Запись остается в базе данных, но ее статус изменяется на `удален`.

Удалить можно только маршрут текущего пользователя.

## Таблицы базы данных

### `sea_routes`

Основная таблица морских маршрутов.

| Поле | Назначение |
|---|---|
| `sea_route_id` | первичный ключ маршрута |
| `sea_route_name` | название маршрута |
| `sea_route_distance_nautical_miles` | расстояние в морских милях |
| `sea_route_average_port_delay_hours` | средняя задержка в портах в часах |
| `sea_route_description` | описание маршрута |
| `sea_route_image_url` | имя файла изображения |
| `sea_route_video_url` | имя файла видео |
| `sea_route_status` | статус маршрута |
| `sea_route_created_at` | дата и время создания |
| `sea_route_formed_at` | дата и время формирования |
| `sea_route_creator_id` | идентификатор пользователя-создателя |

Возможные значения `sea_route_status`:

- `черновик`;
- `опубликован`;
- `удален`.

Статус используется только на бэкенде и в базе данных, в JSON-ответы API не передается.

### `sea_route_users`

Таблица пользователей.

| Поле | Назначение |
|---|---|
| `sea_route_user_id` | первичный ключ пользователя |
| `sea_route_user_login` | логин пользователя |
| `sea_route_user_password` | пароль пользователя |

Пароль пользователя не возвращается клиенту в ответах API.

### `sea_route_likes`

Таблица лайков маршрутов.

| Поле | Назначение |
|---|---|
| `sea_route_like_id` | первичный ключ записи лайка |
| `sea_route_user_id` | идентификатор пользователя |
| `sea_route_id` | идентификатор морского маршрута |

По этой таблице определяется количество лайков маршрута и значение поля `is_liked` для текущего пользователя.

## Текущий пользователь

В лабораторной работе №3 полноценная авторизация еще не реализована.

Текущий пользователь фиксируется на бэкенде:

```go
const currentUserID uint = 1
```

Для получения текущего пользователя используется singleton-функция:

```go
func CurrentUser() *ds.SeaRouteUser
```

Идентификатор текущего пользователя используется при создании, публикации и удалении маршрута, а также при работе с лайками.
